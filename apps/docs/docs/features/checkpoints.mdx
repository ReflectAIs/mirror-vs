# Checkpoints

Mistakes happen. Bad ones. The kind where you stare at your editor and whisper, "What have I done?" Checkpoints are Mirror VS's way of giving you a time machine — automatic Git snapshots that let you rewind when things go sideways.

## What Are Checkpoints?

Every time Mirror VS takes a significant action (editing a file, running a command, creating something new), it automatically creates a Git checkpoint. Think of them as save points in a video game — except instead of respawning at the last castle, you're restoring your codebase to a working state.

### How It Works

Mirror VS uses a **shadow Git repository** — a hidden Git repo that lives alongside your project. It doesn't touch your existing Git history, branches, or remotes. It's like having a secret parallel universe where everything is versioned.

```
Your Project          Shadow Git Repo
┌─────────────┐      ┌─────────────┐
│ main branch  │      │ checkpoint  │
│ your commits │      │ snapshots   │
│ .git/        │      │ .git/       │
└─────────────┘      └─────────────┘
  (untouched)         (auto-managed)
```

## Why Checkpoints Exist

- **Disaster recovery:** AI made a mess? Restore to before the chaos began.
- **Experiment freely:** Let Mirror VS try things. If it doesn't work, roll back. No harm, no foul.
- **Compare changes:** See what happened between checkpoints to understand what changed.
- **Zero guilt experimentation:** That refactor you've been nervous about? Try it. Checkpoints have your back.

## Using Checkpoints

### Automatic Snapshots

Checkpoints are created automatically during a task whenever Mirror VS:

- Edits one or more files
- Creates new files or directories
- Runs terminal commands
- Completes significant subtasks

You don't need to do anything — they just happen. Like magic, but with more Git plumbing under the hood.

### Restoring from a Checkpoint

When you need to undo, you have two options:

#### 1. Restore Files Only

This reverts your working directory to the state it was in at the selected checkpoint. Your task continues as if nothing happened — because as far as the files are concerned, nothing did.

**Use this when:** You want to keep the task going but undo the file changes.

#### 2. Restore Files & Task

This reverts your files *and* rewinds the task conversation. It takes you back to the exact moment the checkpoint was created — files, chat history, and all.

**Use this when:** You want a complete do-over from that point.

### Viewing Checkpoints

Checkpoints appear in the chat interface as you work. You'll see them as timeline markers you can click to view options. Each checkpoint shows:
- When it was created
- What triggered it
- Options to restore

## Technical Details

### How the Shadow Git Works

The shadow repository is initialized in your project's `.git` directory (or a side directory if your project isn't Git-tracked). It's completely separate from your project's own Git history — no branch conflicts, no merge nightmares, no accidental force-pushes.

```
Your Project Root
├── .git/              ← Your real Git repo (untouched)
├── src/
├── .mirror/
│   └── checkpoints/   ← Shadow Git data (if needed)
└── README.md
```

### What Gets Checkpointed

The shadow repo tracks only the files in your workspace — everything Mirror VS can see and modify. It respects:

- **`.gitignore` patterns** — Files you don't track, Mirror VS doesn't either
- **Built-in exclusions** — `node_modules`, `dist`, `build`, and other noisy directories
- **Binary files** — Skipped to keep snapshots lean

### Nested Git Repositories

If nested Git repositories are detected in your workspace, checkpoints are disabled. You'll receive a clear notification when checkpoint initialization fails due to nested repositories. Remove or relocate nested repos to enable checkpoints.

### Concurrency Control

The extension prevents duplicate checkpointing within a single streaming operation. No need to worry about race conditions — Mirror VS has that handled.

## Git Installation

Checkpoints need Git. Here's how to make sure you've got it.

### macOS

**Option 1: Homebrew (recommended)**
```bash
brew install git
```

**Option 2: Xcode Command Line Tools**
```bash
xcode-select --install
```

**Verify:**
```bash
git --version
# Should show something like: git version 2.40.0
```

### Windows

1. Download Git for Windows from [git-scm.com](https://git-scm.com/download/win)
2. Run the installer (default options are fine)
3. Verify in Command Prompt:
   ```cmd
   git --version
   ```

### Linux

**Debian/Ubuntu:**
```bash
sudo apt update && sudo apt install git
```

**Fedora:**
```bash
sudo dnf install git
```

**Arch Linux:**
```bash
sudo pacman -S git
```

**Verify:**
```bash
git --version
```

## FAQs

**Q: Will checkpoints mess with my existing Git repo?**
A: Nope. Shadow repos are completely separate. Your branches, remotes, and commits are safe.

**Q: Can I manually create checkpoints?**
A: Checkpoints are automatic during tasks. You don't need to — and can't — manually trigger them.

**Q: Do checkpoints take up a lot of space?**
A: They use Git's delta compression, so they're surprisingly efficient. But if you run a hundred checkpoints on a massive codebase, yes, it'll add up.

**Q: What happens to checkpoints when a task ends?**
A: Checkpoints are tied to the task session. When the task ends or is cleared, the associated checkpoints are cleaned up.
