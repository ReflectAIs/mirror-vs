# Skills

Skills are Mirror VS's way of becoming an instant expert in whatever you're working on. Need to process PDFs? Generate API docs? Run a specific deployment script? Skills load the right instructions at the right time — no tutorials, no setup, just results.

## What Are Skills?

Skills are lightweight instruction packages — a `SKILL.md` file (with optional bundled resources) that teaches Mirror VS how to handle a specific type of task. They're like cheat codes for your AI coding agent.

```
my-skill/
├── SKILL.md          # Required: instructions + frontmatter
├── templates/        # Optional: template files
├── examples/         # Optional: example code
└── configs/          # Optional: configuration files
```

### Why Skills?

- **On-demand expertise** — Skills load only when needed, keeping the base prompt lean
- **Reusable** — Share skills across projects and teams
- **Bundled resources** — Skills can include templates, examples, and configs that Mirror VS uses during the task
- **Mode-aware** — Skills can target specific modes (Code, Architect, etc.)
- **Progressive disclosure** — Skills are discovered at startup but only loaded when a request matches

## How Skills Work

### The Three Levels of Skill Detail

Skills use progressive disclosure — Mirror VS learns about them in stages:

**Level 1: Discovery**
At startup, Mirror VS reads only the frontmatter of each `SKILL.md`:
```yaml
---
name: pdf-processing
description: Extract text and tables from PDF documents using Python
version: 1.0.0
---
```

This gives Mirror VS a catalog of available skills without loading full instructions.

**Level 2: Instructions**
When a task matches a skill's description, Mirror VS loads the full `SKILL.md` content — including all instructions, code examples, and guidelines.

**Level 3: Resources**
If the skill has bundled files (templates, configs), Mirror VS can access them during task execution.

## Directory Structure

Skills live in specific locations, each with its own priority:

```
~/.mirror/skills/                   # Global skills (all projects)
~/.mirror/skills-code/             # Code mode only (global)
~/.mirror/skills-architect/        # Architect mode only (global)
.mirror/skills/                    # Project skills (overrides global)
.mirror/skills-code/               # Code mode only (project)
.mirror/skills-architect/          # Architect mode only (project)
.agents/skills/                    # Cross-agent skills (lower priority)
.agents/skills-code/               # Code mode only (cross-agent)
```

### File Organization

Each skill is a directory. The directory name becomes the skill's identity:

```
.mirror/skills/
├── pdf-processing/
│   ├── SKILL.md
│   ├── templates/
│   │   └── report-template.py
│   └── examples/
│       └── sample-extraction.py
├── api-docs-generation/
│   ├── SKILL.md
│   └── templates/
│       └── openapi-template.yaml
└── docker-deployment/
    ├── SKILL.md
    ├── docker-compose.yml
    └── nginx.conf
```

### Mode-Specific Skills

Use `skills-{mode}/` directories to restrict skills to specific modes:

```
.mirror/skills-code/
└── react-component-generator/
    └── SKILL.md

.mirror/skills-architect/
└── system-design-review/
    └── SKILL.md
```

A skill in `skills-code/` is only available in Code mode. A skill in `skills/` is available in all modes.

## The SKILL.md File

The heart of every skill. It uses standard frontmatter plus Markdown content.

### Frontmatter Fields

| Field | Required | Description |
|-------|----------|-------------|
| `name` | ✅ | Must match the directory name exactly |
| `description` | ✅ | What the skill does (used for matching) |
| `version` | ❌ | Semantic version (e.g., `1.0.0`) |
| `author` | ❌ | Who created it |

### Example SKILL.md

```markdown
---
name: pdf-processing
description: Extract text and tables from PDF files using Python libraries
version: 1.0.0
---

# PDF Processing Skill

This skill provides instructions for extracting content from PDFs.

## Required Libraries

- `pdfplumber` for text extraction
- `camelot-py` for table extraction
- `PyMuPDF` for OCR fallback

## Extraction Strategy

1. First try `pdfplumber` for standard PDFs
2. If text extraction yields less than 10 chars, fall back to OCR
3. Use `camelot-py` for table detection (lattice mode first, then stream)

## Common Patterns

### Extract All Text
```python
import pdfplumber

with pdfplumber.open("document.pdf") as pdf:
    for page in pdf.pages:
        print(page.extract_text())
```

### Handle Password-Protected PDFs
```python
with pdfplumber.open("document.pdf", password="secret") as pdf:
    ...
```
```

## Skill Discovery

Mirror VS automatically discovers skills:
- **At startup:** All skills are indexed by reading and parsing each SKILL.md
- **During development:** File watchers detect changes to SKILL.md files
- **Mode filtering:** Only skills relevant to the current mode are available

You don't need to register or configure skills — just create the directory structure and Mirror VS finds them.

### Symlink Support

Skills support symbolic links for sharing skill libraries across projects:

```bash
# Share a skill library across projects
ln -s /shared/company-skills ~/.mirror/skills/company-standards
```

The skill name comes from the symlink name (or directory name if not symlinked). The frontmatter `name` field must match this name exactly — you can't create aliases with different names pointing to the same skill.

## Override Priority

When multiple skills have the same name, priority determines which one wins:

1. **Project mode-specific** (`.mirror/skills-code/`) — Highest priority
2. **Project generic** (`.mirror/skills/`)
3. **Global mode-specific** (`~/.mirror/skills-code/`)
4. **Global generic** (`~/.mirror/skills/`)
5. **Cross-agent mode-specific** (`.agents/skills-code/`)
6. **Cross-agent generic** (`.agents/skills/`)

A **project** skill always overrides a **global** skill of the same name. Within the same project level, `.mirror/` overrides `.agents/`.

This lets you:
- Set global standards that work everywhere
- Override them per-project when needed
- Specialize skills for specific modes within each location

## Troubleshooting

### Skill isn't loading

**Symptom:** Mirror VS doesn't use your skill even when you request something matching the description.

**Causes & fixes:**

1. **Name mismatch:** The frontmatter `name` field must exactly match the directory name
   ```markdown
   # ✗ Wrong — directory is "pdf-processing"
   ---
   name: pdf_processing
   ---
   
   # ✓ Correct
   ---
   name: pdf-processing
   ---
   ```

2. **Missing required fields:** Both `name` and `description` are required in frontmatter

3. **Wrong mode:** If the skill is in `skills-code/` but you're in Architect mode, it won't load. Move to `skills/` for all modes or create mode-specific variants.

4. **Description too vague:** Make descriptions specific so Mirror VS can match them to requests
   ```markdown
   # ✗ Vague
   description: Handle files
   
   # ✓ Specific
   description: Extract text and tables from PDF files using Python libraries
   ```

### Skill loads but doesn't help

**Symptom:** Mirror VS reads the skill but doesn't follow instructions.

**Cause:** Instructions may be too general or missing critical details.

**Fix:** Make instructions actionable:
- Include specific function names or library choices
- Provide code templates
- List common edge cases and how to handle them
- Add troubleshooting guidance for the specific task

### Multiple skills conflict

**Symptom:** Unclear which skill Mirror VS will use when multiple might match.

**Cause:** Overlapping descriptions or mode configurations.

**Prevention:**
- Make descriptions distinct and specific
- Use mode-specific directories to separate concerns
- Rely on override priority — project skills override global

### Can't share skills with team

**Symptom:** Want team members to use the same skills.

**Solution:** Place skills in `.mirror/skills/` within your project and commit to version control. Each team member gets the same skills automatically. Teamwork makes the AI work.

## Skills vs Custom Instructions vs Slash Commands

Here's how they stack up:

| Feature | Skills | Custom Instructions | Slash Commands |
|---------|--------|---------------------|----------------|
| **When loaded** | On-demand (when request matches) | Always (part of base prompt) | On-demand (when invoked) |
| **Best for** | Task-specific workflows | General coding standards | Retrieving pre-written content |
| **Can bundle files** | Yes | No | No |
| **Mode targeting** | Yes (`skills-{mode}` directories) | Yes (`rules-{mode}` directories) | No |
| **Override priority** | Project > Global, Mode > Generic | Project > Global | Project > Global |
| **Format** | SKILL.md with frontmatter | Any text file | JSON metadata + content |
| **Discovery** | Automatic (directory scan) | Automatic (directory scan) | Automatic (directory scan) |

**When to use each:**
- **Skills:** "Generate API docs following OpenAPI spec" → Detailed OpenAPI processing instructions load only when needed
- **Custom Instructions:** "Always use TypeScript strict mode" → Applies to all TypeScript work
- **Slash Commands:** `/init` → Returns standardized project setup instructions

## Skill Specification

Mirror VS skills follow the [Agent Skills](https://agentskills.io/) format for skill packaging and metadata. Skills are **instruction packages with optional bundled files** — they don't register new executable tools.

**Required conventions:**
- The frontmatter `name` must exactly match the directory (or symlink) name
- Both `name` and `description` fields are required in frontmatter
- Names: 1–64 chars, lowercase alphanumeric + hyphens, no leading/trailing/consecutive hyphens
- Descriptions: 1–1024 chars (trimmed)

**Mirror VS-specific enhancements:**

Mirror VS adds mode-specific targeting and cross-agent compatibility beyond the base format:

- **Mirror VS-specific locations:** `.mirror/skills/`, `~/.mirror/skills/` (higher priority)
- **Cross-agent locations:** `.agents/skills/`, `~/.agents/skills/` (shared with other agent tools)
- **Mode-specific directories:** `skills-{mode}/` (e.g., `skills-code/`, `skills-architect/`) in both `.mirror/` and `.agents/` paths enable mode targeting
