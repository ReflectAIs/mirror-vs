# Codebase Indexing & Semantic Search

Remember that function you wrote three months ago? The one with the clever name you can't quite recall? Codebase indexing gives Mirror VS a photographic memory of your entire project — so instead of guessing filenames, you can just describe what you're looking for.

## What Is Codebase Indexing?

Codebase indexing is Mirror VS's way of building a searchable brain for your code. It converts your source files into **embeddings** (mathematical representations of meaning) and stores them in a vector database. When you ask a question, it finds the most relevant code by meaning, not just by keyword matching.

**Keyword search:** "Find `getUserById`" — works if you remember the name.
**Semantic search:** "Find the function that fetches a user from the database" — works even when your memory fails you.

## How It Works

```
Your Codebase
     │
     ▼
Parsing (Tree-sitter AST)
     │
     ▼
Chunking (100-1000 char blocks)
     │
     ▼
Embedding (AI model converts to vectors)
     │
     ▼
Qdrant Vector DB (stores & indexes vectors)
     │
     ▼
Semantic Search (query → vector → nearest matches)
```

## Getting Started

### What You'll Need

To use codebase indexing, you need two things:

1. **An embedding provider** — Converts your code chunks into vector embeddings
2. **Qdrant** — A vector database that stores and searches those embeddings

### Setting Up an Embedding Provider

Mirror VS supports several embedding providers:

| Provider | Setup Difficulty | Pricing | Notes |
|----------|:---------------:|:-------:|-------|
| Google Gemini | 🟢 Easy | Free tier available | Currently recommended — free tier is generous |
| Ollama | 🟢 Easy | Free (local) | 100% offline, 0% data leaving your machine |
| OpenAI | 🟡 Medium | Pay-per-token | Reliable, well-documented |
| Jina | 🟡 Medium | Pay-per-token | Specialized for code embeddings |
| Mistral | 🟡 Medium | Pay-per-token | Good multilingual support |
| OpenRouter | 🟡 Medium | Pay-per-token | Access to multiple models |
| Openai-compatible | 🔵 Flexible | Varies | Bring your own compatible provider |

### Configuring Your Provider

1. Open Mirror VS settings (`Cmd/Ctrl + ,`)
2. Search for "Codebase Indexing"
3. Select your embedding provider from the dropdown
4. Enter your API key (if required)
5. Click "Initialize Index"

### Setting Up Qdrant

Qdrant is the vector database that stores your embeddings. You have two options:

**Option 1: Docker (recommended)**
```bash
docker run -p 6333:6333 qdrant/qdrant
```

**Option 2: Cloud** — Use [Qdrant Cloud](https://qdrant.tech/) for a managed instance

Then configure the Qdrant URL in Mirror VS settings (default: `http://localhost:6333`).

## How Indexing Works Under the Hood

### Intelligent Parsing

The system uses a layered parsing strategy:

1. **Tree-sitter First** — For supported languages, it uses AST parsing to identify semantic code blocks (functions, classes, methods)
2. **Markdown Support** — Indexes Markdown files by treating headers as semantic entry points
3. **Intelligent Fallback** — For unsupported file types, it falls back to line-based chunking

**Block Sizing:**
- Minimum: 100 characters
- Maximum: 1,000 characters
- Large functions are split intelligently at logical boundaries

### File Filtering

The indexer respects your project's ignore patterns:
- Files matching `.gitignore` patterns
- Files matching `.mirrorignore` patterns
- Binary files and images
- Files larger than 1MB

**Important:** Make sure your `.gitignore` includes common dependency folders like `node_modules`, `vendor`, `target`, etc. The system relies on these patterns to know what to skip.

### Incremental Updates

- **File Watching** — Monitors your workspace for changes in real-time
- **Smart Updates** — Only reprocesses modified files
- **Branch Aware** — Automatically handles Git branch switches
- **Hash-based Caching** — Avoids reprocessing unchanged content
- **Multi-Folder Workspaces** — Each folder in a multi-folder workspace maintains its own index with separate settings and status

## Best Practices

### Writing Effective Queries

Instead of searching for exact syntax, describe what you want:

- ❌ `const getUser`
- ✅ `function to fetch user from database`

Use natural language:
- "authentication middleware"
- "error handling for API requests"
- "database connection setup"

### Security Considerations

- **API Keys** — Stored securely in VS Code's encrypted storage
- **Code Privacy** — Only small code snippets are sent for embedding
- **Local Processing** — All parsing happens locally on your machine
- **Access Control** — Respects file permissions and ignore patterns

## Troubleshooting

### Connection Issues

**"Connection to Qdrant failed"**
- Ensure Qdrant is running (`docker ps` to check)
- Verify URL matches (default: `http://localhost:6333`)
- Check firewall/network policies
- For cloud instances, confirm URL and API key

**"Invalid API Key" or "401 Unauthorized"**
- Double-check your API key is correct
- Ensure the key has necessary permissions
- For Ollama, verify the service is running

### API Key Format Errors ("ByteString conversion")

- **Symptom:** Error mentions "ByteString conversion" during indexing or when saving settings
- **Likely cause:** Your embedding provider API key contains invalid/special characters or hidden whitespace
- **Fix:**
  - Regenerate a fresh API key from your provider dashboard
  - Paste it again, ensuring no leading/trailing spaces or hidden characters
  - Mirror VS will display a clear validation message if the key is invalid

### Model Issues

**"Model Not Found"**
- For Google Gemini: Ensure the model name is correct (e.g., `gemini-embedding-001`)
- For other providers: Consult their documentation for available models and proper naming

### Indexing Issues

**"Stuck in Error State"**
1. Check connection issues first
2. Click "Clear Index & Re-index" in settings
3. This resolves corrupted cache or collection issues

**"Indexing Taking Too Long"**
- Normal for large codebases (10k+ files)
- Check `.gitignore` includes large directories
- Consider adding patterns to `.mirrorignore`

## Using the Search Feature

Once indexed, Mirror VS can use the [`codebase_search`](/advanced-usage/available-tools/codebase-search) tool to find relevant code semantically.

**Example Natural Language Queries:**
- "How is user authentication handled?"
- "Database connection setup"
- "Error handling patterns"
- "API endpoint definitions"
- "Component state management"

The tool provides:
- Relevant code snippets
- File paths with line numbers
- Similarity scores
- Direct navigation links

## Privacy & Data Security

**Your code stays private:**
- Only small code chunks (100-1000 chars) are sent for embedding
- Embeddings are one-way mathematical representations — you can't reconstruct code from them
- Local parsing means full files never leave your machine
- Use Ollama for completely offline operation

**Data Storage:**
- Vectors stored in your chosen Qdrant instance
- You control where data lives (local or cloud)
- Easy to delete: just clear the index

## Current Limitations

- **File Size** — 1MB maximum per file
- **External Dependencies** — Requires embedding provider + Qdrant
- **Language Support** — Best results with Tree-sitter supported languages
